# U1-3 — мельница, сыроварня и общее производство

Реализовано 13.11.2026. Пункт завершён; общая фаза U1 остаётся открытой.

## Результат

| Постройка | Цена / footprint | Рецепт | Реальное время | Продажа результата |
|---|---|---|---|---|
| Яблочный пресс | прежние 80 / 2×2 | 3 яблока → 1 сок | прежние 60 секунд | прежние 65 монет |
| Мельница | 80 / 5×4 | 3 пшеницы → 1 мука | 30 секунд | 22 монеты |
| Сыроварня | 100 / 5×6 | 2 молока → 1 сыр | 90 секунд | 80 монет |

Начальный баланс новых производств выбран при реализации; он доступен в ProductionRecipe, интерфейсе и справочнике. Стабильные ID: mill, cheese_dairy, flour, cheese; рецепты wheat_to_flour, milk_to_cheese, прежний apple_to_juice.

ProductionBatches хранит одну неполученную партию на ID экземпляра постройки. Запуск списывает сырьё ровно один раз; очередь отсутствует. Сбор — отдельная операция, поэтому повторный Collect не запускает следующую партию. При переполнении продукта партия остаётся внутри. Таймер записан в UTC, как у прежнего пресса: меню и отсутствие запущенной игры не замораживают срок готовности. Перенос/поворот не меняет ID партии. Занятую постройку удалить нельзя.

Сервис общий для трёх фиксированных рецептов; универсальная фабричная система не добавлена. ApplePresses оставлен маленьким адаптером для прежней цели первой продажи сока.

Общее окно показывает входное сырьё, требуемое и имеющееся количество, выход, цену продажи, прогресс, оставшееся время, запуск и ручной сбор. Оно использует существующий стек меню, паузу, фокус/Esc и масштабирование по доступной области. Открытие — обычное действие рядом с постройкой, через InteractionSystem. Дистанция до крупных зданий считается от коллайдера; действия кнопок повторно проверяют доступность. При загрузке старое открытое окно закрывается. Текст цели пресса обновлён под кнопки окна.

FarmProductionUI создаёт свои компактные элементы один раз в Awake существующего gameplay-меню. Пересборка карты/Prototype не требуется. Новые Resources-префабы разрешаются как в runtime, так и в старой команде метрического авторинга.

## Ресурсы

Resources/FarmContent/Mill.prefab использует подготовленную башенную мельницу, Dairy.prefab — подготовленную сыроварню с рабочим столом, бидоном и сыром. Исходные U1-0/импортированные модели не изменены. У обоих дверное полотно 1,98 м; мельнице добавлен входной объём, у сыроварни адаптирован отдельный дверной элемент. Финальные размеры примерно 4,03×5,80×2,65 и 3,92×3,20×4,75 м, внутри footprint с запасом. Статическая модель лопастей сохранена; анимация вращения в задачу не добавлялась.

Flour.asset/Cheese.asset используют подготовленные иконки и зарегистрированы в инвентаре/продаже. Явная подготовка: `Tools / My Little Farm / University / Prepare U1-3 Production`; не инициализирует ферму и не сохраняет открытую сцену.

## Сохранения

Схема v15 добавляет productionBatches: ID экземпляра постройки, ID рецепта, начало и срок готовности, ID и количество выходного продукта. Прежние ID пресса/сока и семантика реального времени сохранены. Список принадлежит снимку конкретной фермы; глобального состояния партий нет. При восстановлении список полностью заменяется, включая пустое состояние.

v12–v14 читают applePressBatches и переносят каждый readyAtUnixMs без изменения. Старый результат — один apple_juice; начало прогресса восстанавливается как deadline − 60 секунд. v1–v11 не содержат партий пресса. Новые Capture записывают только общий список, legacy-список пустой.

В ручной проверке найден и исправлен повторный проход миграции: TryReadValidated и Restore оба валидируют данные. Удалять legacy-источник из кандидата на первом проходе нельзя — это обнуляло партии на втором. Итоговая миграция повторяемая; ниже приведены наблюдения после исправления. Подготовленный тест использует именно LoadFromPath, чтобы покрыть оба прохода.

Валидация проверяет владельца, соответствие рецепта постройке/результату, количество, сроки и уникальность партии. Существующие атомарная запись, backup и маршрутизация слотов сохранены.

## Короткая ручная проверка

Использованы отдельные вызовы игровых компонентов и реальных onClick-обработчиков в изолированной Play Mode-сцене. Test runner, assertions и пакетный прогон не запускались. За пределами проверки остаётся полный путь клавиатура/мышь → три слота → выход из Windows Player → повторный запуск.

Наблюдения записаны в [manual-observations.json](manual-observations.json).

- Постройки куплены через BuildSystem за диагностические деньги. Проверки физического свободного места действуют: поворот сыроварни первоначально отклонён из-за стоящего рядом персонажа; после его перемещения поворот прошёл.
- Все три кнопки «Запустить» создали по одной партии и списали ровно 3 яблока, 3 пшеницы и 2 молока. Исходный запас был выдан только диагностической ферме.
- Сохранение active-profile-v15.json загружено после полного stop/play. Все три startedAt/readyAt совпали со снимком. Проверка прошла до готовности последней партии, без ускорения UTC.
- Пресс повернут с активной партией: срок не изменился. Удаление отклонено с объяснением. Сыроварня также повёрнута с сохранением партии при повторном восстановлении active-profile.
- При количестве муки int.MaxValue сбор отказал, партия осталась. После освобождения инвентаря кнопка выдала одну муку; повторный вызов не дублировал продукт.
- По реальным срокам получены одна мука, один сок, один сыр. Ранний Collect сыроварни оставался недоступен. После сбора при отсутствии молока запуск отказал без новой партии.
- Продажа трёх продуктов через FarmMarket: +167 монет, итоговый баланс 407. После загрузки sold-profile-v15.json партии остались пустыми.
- Переключение отдельных idle/active/sold файлов дало 0/3/0 партий; точные сроки активного файла сохранены. Это проверка замены снимков, не полный прогон интерфейса трёх слотов.
- Из контрольного U1-0 orchard-and-press-v12.json создана отдельная копия с двумя партиями: готовой и ожидающей. Исходный baseline не перезаписан. Файл legacy-ready-and-running-v12.json загрузился, готовый пресс выдал сок один раз, повторный сбор отказал; второй не выдавал продукт раньше сохранённого срока. После загрузки производного v15 и ожидания второй пресс выдал ровно ещё один сок, всего два. Новая запись legacy-collected-v15.json содержит 0 партий.

## Изоляция и состояние проекта

Исходная Prototype уже была dirty. До проверки её состояние в памяти сохранено отдельным снимком Assets/_Recovery/U1-3SourceBackup.unity. Исходная сцена оставалась загружена с временно выключенным корнем; отдельная U1-3Review не запускала slot persistence, HasActiveFarm был false. Для диагностического открытия меню использован его внутренний Show, после чего проверялись реальные кнопки с обычными проверками дистанции/сырья. Чтение/запись снимков выполнялись только по явно указанным путям Verification/U1-3; реальные пользовательские фермы не были фикстурами.

Копия закрыта и удалена до включения исходного корня. Prototype восстановлена в Edit Mode, GridSystem включён и вновь владеет singleton; прежние несохранённые изменения оставлены несохранёнными. Резервный снимок оставлен. Существующие незакоммиченные изменения других пунктов сохранены. Автоматическая пересериализация ProjectSettings сохранена отдельно, исходный файл восстановлен.

## Проверки и оставшаяся приёмка

Скрипты, ассеты и три ProductionIntegrationTests скомпилированы Unity. Тесты подготовлены для смеси партий/переноса/round-trip, вместимости/повторного входа и загрузки реального файла v12/ошибочного рецепта. **Не запускались**, согласно AGENTS.md.

Не выполнялись Verify-Scripts.ps1, полные/выборочные автоматические тесты, Player build, performance-прогон, полный интерфейсный обход трёх слотов и длительная игра. Они остаются на закрытие крупной фазы. Финальная компиляция завершена без ошибок. В Console осталось прежнее предупреждение obsolete API в GameBootstrap.cs:357 (console-final.json). Редактор — в Edit Mode, Prototype dirty, GridSystem включён; временная сцена удалена (editor-final.json).
